## 1. UX 설계 원칙

| # | 원칙 | 구현 방침 |
|---|---|---|
| U1 | **페르소나별 진입 경로 분리** | 현업은 마법사·템플릿에서 시작, 엔지니어는 캔버스·코드에서 시작. 첫 화면에서 갈림 |
| U2 | **점진적 노출 (Progressive Disclosure)** | 기본 화면에는 필수 설정만. 고급 설정(컨텍스트 예산, 재시도 정책 등)은 "고급" 패널로 접힘 |
| U3 | **즉시 피드백** | 모든 편집은 실시간 검증(스키마는 프런트, 참조는 디바운스 API). 오류는 해당 노드/필드에 인라인 표시 |
| U4 | **만들면서 테스트** | 빌더 화면 안에 플레이그라운드 상주 — 편집→테스트 전환 비용 0 |
| U5 | **신뢰 가시화** | 응답의 인용·가드레일 통과·평가 점수를 UI 1급 요소로 항상 노출 (Enterprise 신뢰성 원칙의 UX 대응) |
| U6 | **되돌릴 수 있음** | 모든 파괴적 행위는 확인 + 버전 롤백 경로 제공. 삭제는 소프트 삭제 후 유예 |
| U7 | **용어는 현장 언어로** | UI 라벨에 개발 용어 최소화 ("DSL 컴파일" ❌ → "구성 검사" ✅). ko/en 리소스 분리 |

### UX 품질 목표 (측정)

| 지표 | 목표 |
|---|---|
| TTFA (Time-to-First-Agent): 현업이 템플릿으로 첫 에이전트를 만들어 테스트 응답을 받기까지 | **30분 이내** |
| 마법사 완주율 | 80% 이상 |
| HITL 승인 처리 소요 (알림 수신→결정) | 3클릭 이내 처리 가능 |
| 파일럿 SUS(System Usability Scale) 조사 | 70점 이상 |

## 2. 정보 구조 (IA)

```
Studio
├── 🏠 홈                    # 역할별 대시보드 + 에이전트 카탈로그
├── 🤖 에이전트
│   ├── 목록/카탈로그         # 검색·도메인 태그·상태 필터
│   ├── 빌더 (캔버스|코드)     # 핵심 작업 화면 (3장)
│   ├── 플레이그라운드         # 독립 실행도 가능
│   └── 버전/배포             # 환경별 상태, 승격, 롤백
├── 📚 지식
│   ├── Knowledge Space 목록/설정
│   ├── 문서 관리             # 업로드, 색인 상태, 검수함
│   ├── 온톨로지/용어사전      # (P1)
│   └── 검색 테스트           # 검색 디버거
├── ✅ 평가
│   ├── 골든셋 관리
│   ├── 평가 실행/리포트
│   └── 휴먼 채점함           # (P1)
├── 📥 승인함 (Inbox)         # HITL 승인 + 배포 승인 통합
├── 📊 운영                   # 모니터링 대시보드, 실행 이력, 피드백
└── ⚙️ 관리                   # 사용자/역할, 모델 별칭, 도구/커넥터, 정책, 감사
```

- 좌측 글로벌 내비게이션 고정. 상단에 **워크스페이스(프로젝트) 전환기** + 환경 표시
  배지(개발/스테이징/**프로덕션**은 색상 구분 — 실수 방지).
- RBAC에 따라 메뉴 자체가 숨겨진다 (보이는데 눌리지 않는 UI 금지).

## 3. 핵심 화면 설계

### 3.1 에이전트 빌더 (핵심 화면)

```
┌────────────────────────────────────────────────────────────────────┐
│ ehs-msds-qa v1.3(draft)   [구성 검사 ✓] [저장] [버전 생성] [배포▾]  │ ← 헤더: 상태·주작업
├──────────┬──────────────────────────────────────┬──────────────────┤
│ 노드      │                                      │ 속성 패널         │
│ 팔레트    │        비주얼 캔버스 (React Flow)      │ (선택 노드의)     │
│          │                                      │ · 프롬프트 편집   │
│ LLM      │   [분류] ─▶ [지식검색] ─▶ [LLM응답]    │ · 모델 별칭 선택  │
│ 지식검색  │                │                     │ · 지식/도구 바인딩│
│ 도구      │                └▶ [승인게이트] ─▶ …   │ · ▸ 고급 설정     │
│ 분기      │                                      │                  │
│ 승인게이트 │   (오류 노드는 빨간 배지 + 인라인 메시지) │ [캔버스|코드] 토글│
├──────────┴──────────────────────────────────────┴──────────────────┤
│ ▼ 플레이그라운드 (접이식 하단 패널)                                   │
│  💬 테스트 대화창          │ 🔍 실행 인스펙터: 노드 타임라인·검색결과· │
│                           │    프롬프트 원문·토큰/지연 (탭)           │
└────────────────────────────────────────────────────────────────────┘
```

- **[캔버스|코드] 토글**: 우측 상단. 코드 모드는 같은 자리에서 Monaco(YAML)로 전환 —
  동일 문서의 두 뷰 (ADR-10). 분할 뷰(캔버스+코드 동시)는 P1.
- 실행 중에는 캔버스 노드가 상태 색(실행 중=파랑 펄스, 완료=초록, 실패=빨강)으로 변하고,
  노드 클릭 시 해당 스텝의 입출력이 인스펙터에 표시 (FR-STD-01 실행 시각화).
- 헤더의 **[구성 검사]** 는 컴파일 ①~③단계 결과 요약 (오류 n건 → 클릭 시 해당 위치로 점프).

### 3.2 에이전트 생성 마법사 (FR-STD-08 — 현업 진입점)

```
① 무엇을 하는 에이전트인가요?   → 과업 유형 선택 (Q&A / 데이터 분석 / 리포트 생성 / 업무 절차)
② 템플릿 추천                  → 도메인+유형 기반 스타터 제시 (예: "안전 절차 Q&A")
③ 지식 연결                    → 접근 가능한 Knowledge Space 선택, 없으면 문서 업로드 유도
④ 도구 연결 (선택)             → 허용된 도구 목록에서 선택, 실행 정책 기본값 안내
⑤ 지시문 초안                  → ①~④ 입력으로 LLM이 시스템 프롬프트 초안 생성 → 사용자 수정
⑥ 바로 테스트                  → 인라인 플레이그라운드에서 3~5회 문답
⑦ 마무리                       → Readiness Check 표시 (골든셋 미작성 등 미비 항목 안내)
```

- 각 단계 이탈 시 초안 자동 저장. 완료 후 빌더 화면으로 자연 전환 (마법사는 빌더의
  게이트가 아니라 지름길 — 언제든 빌더로 나갈 수 있음).

### 3.3 승인함 (HITL Inbox)

- HITL 승인과 배포 승인을 **하나의 인박스**로 통합 (승인자는 유형을 구분할 필요 없이
  "내가 결정할 일" 목록을 본다).
- 카드 구성: 요청 요약(무엇을 실행하려는가) / 근거(에이전트가 제시한 컨텍스트·인용) /
  영향(어떤 시스템에 무엇을 쓰는가) / 결정 버튼 [승인] [수정 후 승인] [반려+사유].
- 배포 승인 카드에는 평가 리포트 요약·변경 diff 링크 자동 첨부 (FR-GOV-04).
- 반응형 레이아웃 — 모바일 브라우저에서 결정 가능 (승인 지연은 파일럿 성패 요소).

### 3.4 지식 관리

- Space 목록: 문서 수·색인 상태·마지막 갱신·연결된 에이전트 수를 카드로.
- 문서 테이블: 상태(색인 완료/실패/검수 대기), 유효기간·개정 상태 배지(법규 문서 —
  FR-KNW-08). 실패 행 클릭 → 실패 단계·사유·재시도 버튼.
- **검색 테스트 탭**: 질의 입력 → 단계별 결과(하이브리드 후보 → 리랭킹 후 순위 변화)를
  나란히 표시. "이 문서가 왜 안 나오지?"를 스스로 진단 가능하게 (지식 관리자 핵심 도구).

### 3.5 평가 리포트

- 버전 비교 뷰: 이전 버전 대비 총점·항목별 점수 델타(▲▼), 회귀한 케이스 강조.
- 실패 케이스 행 → 트레이스 드릴다운(어느 노드·어느 검색·어느 프롬프트가 문제인지) →
  "플레이그라운드에서 재현" 버튼 (FR-OPS-01 연계).

### 3.6 최종 사용자 챗

- 심플 챗 UI: 스트리밍 응답, **인용 각주(클릭 시 원문 청크·문서 뷰어)**, 피드백 👍/👎+사유,
  면책 고지 영역(도메인 안전 규칙 시 자동 표시), 대화 이력.
- 임베더블 위젯(P1)은 동일 컴포넌트의 iframe/웹컴포넌트 패키징.

## 4. 상호작용 공통 규칙

| 상황 | 규칙 |
|---|---|
| 오류 메시지 | ① 무엇이 잘못됐는지 ② 어떻게 고치는지 ③ 해당 위치로 이동 링크. 코드/스택트레이스는 "자세히"로 접힘 |
| 로딩/스트리밍 | 2초 이상 걸리는 작업은 진행 표시 필수. LLM 응답은 항상 토큰 스트리밍 + 중단 버튼 |
| 저장 | 빌더는 자동 저장(draft) + 명시적 "버전 생성"(불변). 저장 상태를 헤더에 상시 표시 |
| 긴 목록 | 서버 페이지네이션 + 컬럼 필터. 카탈로그는 태그 파셋 검색 |
| 파괴적 행위 | 프로덕션 관련은 리소스 이름 입력 확인. 모든 확인 다이얼로그에 영향 범위 명시 |
| 단축키 | 빌더: 저장(⌘S), 테스트 실행(⌘Enter), 검증(⌘K) — 파워유저 경로 |
| 접근성 | WCAG 2.1 AA 목표: 키보드 내비게이션, 색상 외 상태 표시(아이콘 병행), 4.5:1 대비 |
| i18n | ko 기본, en 완전 지원. 날짜/숫자 로케일 처리. 문자열 하드코딩 금지 (NFR-09) |

## 5. 디자인 시스템

- 컴포넌트 라이브러리: **shadcn/ui + Tailwind CSS** (커스터마이즈 용이, 의존성 경량) —
  배포 프로파일의 브랜딩(로고·주색상) 토큰 주입 지원.
- 다크 모드: P2. 차트: Recharts (운영 대시보드·평가 추이).
- 상태 색 체계 고정: 성공=green, 실행 중=blue, 대기/검수=amber, 실패/위험=red,
  프로덕션 배지=purple — 전 화면 일관.
