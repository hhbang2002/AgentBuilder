# 요구사항 추적 매트릭스 갱신

산출물은 [../../docs/traceability.md](../../docs/traceability.md) 하나다. Stage 0
완료 시점 기준으로 초기 버전이 이미 작성되어 있다 — 이 스킬은 그것을 최신 상태로
유지하는 절차다.

## 절차

1. **소스에서 FR 참조 수집**: 코드 주석·docstring에 박힌 `FR-XXX-NN` 패턴을 검색
   (`grep -rn "FR-[A-Z]*-[0-9]*" src/`). 이 저장소는 커밋 메시지와 docstring에 FR
   번호를 표기하는 관례를 쓴다 (루트 CLAUDE.md "작업 방식" 참고).
2. **테스트에서 FR 참조 수집**: 같은 패턴으로 `tests/` 검색. docstring이나 주석에
   FR 번호가 없는 테스트는 무엇을 검증하는지 보고 대응되는 FR을 추론한다.
3. **기능정의서와 대조**: `docs/01-functional-specification.md` §5의 FR 목록(특히
   P0 표기 항목)을 훑으며, 2~3단계에서 못 찾은 FR이 있으면 "⬜ 미구현"으로 남긴다.
4. **상태 판정 기준**:
   - ✅ 테스트로 검증됨: 해당 기능을 정확히 검증하는 테스트가 있고 통과한다
   - 🟡 부분구현: 코드는 있지만 (a) 테스트가 없거나 (b) FR이 요구하는 범위 중 일부만
     구현됨 (예: DSL 표현은 되지만 실행 로직은 아직 없음) — 이 경우 무엇이 남았는지
     한 줄로 적을 것
   - ⬜ 미구현: 코드 없음
5. **`docs/traceability.md` 갱신**: 표를 다시 쓰고, 문서 하단 "커버리지 요약"의
   숫자를 재계산한다.
6. **다음 Stage 섹션 추가**: 새 Stage가 시작되면 (`docs/03-development-guide.md` §5
   기준) 해당 Stage의 AC와 관련 FR을 새 절로 추가한다 (Stage 0 절의 형식을 따를 것).

## 보고 형식 (사용자가 "이 FR 구현됐어?"라고 물었을 때)

FR 번호 → 상태 → 근거 파일:줄 → (부분구현이면) 남은 작업을 2~3문장으로. 매트릭스
전체를 다시 붙여넣지 말고 물어본 FR만 답한다.
